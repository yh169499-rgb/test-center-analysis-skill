# 秒懂测试执行与分析报告整合设计

日期：2026-09-29

## 目标

把 `miaodong-cli` 的测试执行能力与现有 `test-center-analysis` 的误判检查、统计和 HTML 报告能力整合到一个用户入口中。用户既可以从测试集开始运行，也可以给出已完成的任务；测试结束后生成可追溯的本地 HTML 报告。公开发布仍是可选的最后一步。

目标仓库为 `yh169499-rgb/test-center-analysis-skill`，继续使用技能名 `test-center-analysis`，不新增重复的顶层技能。

## 范围

### 包含

- 调用已安装的 `md` 执行测试、等待状态并导出逐条 JSONL。
- 把 `md test results` 的单任务 JSONL 转换为现有 `schemaVersion = 1` 数据集。
- 支持“从测试集开始”和“从已有任务开始”两种入口。
- 在 HTML 中单独披露未跑、空跑、异常、完成状态未知和判定未知。
- 保留原来的 Request URL、完整 JSON 导出、误判检查、判定调整和自定义报告能力。
- 保留本地校验以及可选的 HTML Gallery 发布流程。

### 不包含

- 不修改 `Spider615/miaodong-cli` 仓库或它的远端接口。
- 不绕过 `md` 的费用、插件、跑前检查和确认码机制。
- 不自动修改测试中心判定、测试用例、画布或后台数据。
- 不把真实测试结果、身份、令牌、Authorization、客户截图或生成的报告提交到 GitHub。
- 不把回复中出现“转人工”当作实际转接证据。

## 用户入口

### 入口 A：从测试集开始

用户提供智能体、测试集；版本、轮数、并发、任务名仅在用户指定时传入，否则采用 `md` 的安全默认值。

流程：

1. `md test run` 做跑前检查和费用预估。
2. 如果 `md` 返回确认码，停止并单独向用户说明智能体、测试集、轮数、费用或插件原因；用户确认后才携码重试。
3. 任务创建后立刻用 `md test status <任务> --wait` 跟进；单次最长 540 秒，未结束则继续等待，不重复创建任务。
4. 任务完成后运行 `md test results <任务> --bot <智能体> --deep --out <私有目录>/results.jsonl`。
5. 转换、分析并生成 HTML。

### 入口 B：从已有任务开始

用户提供智能体和任务名、完整 ID 或可唯一解析的 ID 前缀。先用 `md test status` 确认状态；仍在运行时按用户要求等待，完成后从第 4 步继续。若任务暂停、失败或还有未跑记录，报告必须明确披露，不能称为完整跑完。

### 入口 C：保留现有数据入口

继续接受完整 Request URL + Authorization，或完整本地 API JSON 导出。旧用法和原有报告结果不得被新的 `md` 入口破坏。

## 组件与职责

### `miaodong` Skill / `md`

负责识别智能体、跑前检查、费用和插件确认、创建任务、查看状态、止损、深取实际回复以及导出 JSONL。整合技能只调用公开 CLI，不读取 `~/.miaodong/md` 身份文件，也不直接调用秒懂接口。

### `prepare_md_results.py`

新增的确定性适配器，只读取单任务 JSONL，校验完整性并输出：

- `raw-md-results.jsonl`：输入的逐行原文副本，权限 0600。
- `dataset.json`：供现有报告生成器使用的规范化数据，权限 0600。

拒绝覆盖已有文件、符号链接、重复 JSON 字段、混合任务、重复执行标识、非法类型和明显凭据。错误信息不能回显原始用户对话或凭据。

### `build_report.py`

复用现有报告逻辑，并增加空跑统计。继续负责基础通过率、失败案例、精确去重输入输出、可选耗时/分组/转人工和 HTML 安全转义。

### `html-gallery`

仅在用户明确要求发布时加载。所有内容调整和本地验证完成后，必须询问本次是给客户还是同事看并等待明确答复；客户为 `open`，同事为 `login`，密码保护按明确要求使用 `public`。没有发布要求时只交付本地 HTML。

## `md` JSONL 到数据契约的映射

每行必须属于同一非空 `task`，并含 `caseId`、`name`、`user`、`expect`、`passed`、`verdict`、`reply`、`actions`、`testExecId`、`noop`、`notRun` 等由当前 `md test results` 产生的字段。允许当前 CLI 的已知附加字段，但不会把内部标识渲染到公开报告。

| `md` 字段 | 规范化字段 | 规则 |
| --- | --- | --- |
| `task` + `testExecId` | `id` | 优先使用测试执行 ID；缺失时用 task、caseId 和同任务稳定序号组成私有唯一键 |
| `name` | `caseName` | 保留原文 |
| `user` | `input` | 保留原文，不 trim、不改写 |
| — | `context` | 设为空对象，并在来源警告中说明 `md` JSONL 不含完整多轮上下文 |
| `reply` + `actions` | `actual` | 组织成 `{reply, actions}`，防止动作信息在去重时丢失 |
| `expect`、`verdict`、`reply`、`passed` | `assertions` | 生成一个可追溯断言对象；空跑、未跑的断言判定为 null |
| `passed` | `originalPassed` | 仅正常执行且非空跑时采用布尔值；空跑和未跑为 null |
| `notRun` | `completed` | true 时为 false；正常执行和空跑为 true |
| `noop` / `notRun` | `status` | 分别为 `noop` / `not_run`；正常记录为 `completed` |
| `scenario` | `scene` | 空字符串转 null，其余保留 |
| `ms` | `durationMs` | 仅接受非负有限数 |
| `caseId`、`execId`、`testExecId`、`online`、`cost` | `attributes` | 仅供私有追溯和按需统计；默认不渲染标识 |
| — | `handoff` | 默认 null；文本和扁平动作摘要不足以自动证明转接 |

`reply` 或 `actions` 为空仍是实际结果的一部分，不用占位文案替换。

## 统计口径

- 总执行记录：JSONL 的全部行。
- 正常可判定执行：`completed = true`、`status != noop` 且报告判定为布尔值。
- 业务通过率：正常通过数 ÷ 正常可判定执行数。
- 未跑：单独计数，不进入通过率。
- 空跑：单独计数，不作为正常失败，不进入业务通过率；报告说明秒懂原生汇总可能把空跑纳入执行次数，因此两种口径不能混用。
- 失败案例：只列正常执行且报告判定为 false 的记录；空跑另设专门章节或指标。
- 去重：精确 `(input, context)` 分组，同组内精确 `actual` 合并；空白、大小写、数组顺序和 JSON 类型均保留。
- 转人工率：没有结构化证据时保持未知。若后续通过完整轨迹形成 annotations，才进入已知分母。
- 耗时：只纳入正常完成、非负且单位确认为毫秒的记录；空跑可单独披露但不混入业务耗时。

## 报告内容

基础内容：

- 总记录、正常可判定数、通过、未通过、业务通过率。
- 未跑数、空跑数、判定未知、状态异常和数据覆盖说明。
- 所有正常未通过的具体案例及期待、断言结论、实际回复和实际动作。
- 全部不重复的实际输入输出及出现次数、通过/失败/未纳入统计次数。

按用户需要增加转人工、场景、渠道、耗时、稳定性、批次对比或自定义章节；缺少证据时显示无法统计及原因，不编造数值。

## 错误与中断处理

- `md` 未安装：给出仓库和安装说明，不自动从未知位置安装。
- 身份缺失或过期：严格走 `md auth snippet` / `md auth import` 流程，不让用户把凭证贴到对话。
- 跑前检查失败：列出问题并停止；只有用户明确要求才使用 `--allow-preflight-errors`。
- 费用或插件确认：保持 `md` 的确认码和单独确认要求。
- 建任务响应不确定：先查最近任务，不自动重跑。
- 等待超时：继续同一任务，绝不新建重复任务。
- `--deep` 局部失败：保留该行的失败标记并披露覆盖率；其他记录继续处理。
- JSONL 含未跑、混任务、重复记录或字段漂移：不宣称完整，给出可行动的修复说明。
- HTML 生成或发布失败：不捏造链接，不覆盖已有本地产物。

## 安全与权限

- 测试执行可能花钱或调用插件，权限边界完全继承 `md`。
- JSONL、规范化数据、调整和报告放在任务独立私有目录，不放进技能仓库。
- GitHub 只提交技能源码、文档、测试和合成 fixture。
- 报告生成前继续扫描 Authorization、Cookie、JWT、密码和令牌模式。
- 报告默认不公开 task、case、exec、组织、来源 URL 等内部标识。
- 发布不是生成报告的隐含授权；每次发布或更新都按本次受众确认。

## 验证方案

### 适配器单元测试

- 正常通过、正常失败、空跑、未跑、未知字段、空回复和动作。
- 同输入不同输出、同输出混合判定、重复轮次。
- 混合任务、重复 ID、缺失稳定 ID、无效 JSONL、重复 JSON 字段。
- 0600 权限、拒绝覆盖、拒绝符号链接、失败不留部分文件。
- 凭据模式拒绝且错误不回显原文。

### 报告回归测试

- 空跑和未跑不进入业务通过率。
- 空跑不出现在正常失败案例中。
- 全部分组计数相加等于输入总记录数。
- 现有 API JSON、调整、转人工、耗时、搜索、分页、打印和注入防护测试保持通过。

### 端到端测试

使用完全合成的 `md results.jsonl`：适配 → 数据集 → HTML → summary；验证总数、业务通过率、空跑、未跑、失败案例、去重组和脚本语法。测试不联网、不创建真实任务、不发布页面。

## 发布与兼容

实现完成后：

1. 运行全套测试、技能校验、合成端到端和公开文件凭据扫描。
2. 更新同一公开仓库，不上传真实数据或报告。
3. 更新本机安装副本并对比源码哈希。
4. 保留现有仓库链接和 Skill 名，现有使用方式继续有效。
5. 对外说明：完整的“运行测试”能力依赖另行安装并授权 `miaodong-cli`；只分析 API JSON 或生成本地报告不依赖 `md`。HTML Gallery 仍只在发布报告时需要。

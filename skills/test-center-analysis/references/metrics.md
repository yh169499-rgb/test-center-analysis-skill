# 报告指标与章节

## 先确定本次需求

基础内容总是包括通过率、具体失败案例、全部不重复的实际输入输出。用户可以用自然语言要求额外指标、分组、对比、解释和展示形式，不限于预置列表。额外需求必须先确定：字段来源、分子、分母、统计对象（执行/用例/会话）、时间范围、排除项、未知项和证据。

没有影响口径的歧义就直接采用并说明默认；有实质歧义时只询问必要问题。不能为了显示某个指标而新采集无关系统、索取新权限或编造数据。

## 基础统计

- 默认展示的是**业务通过率**：正常完成、不是 `noop` / `not_run` / 错误或未知状态，且有明确报告判定的执行次数为分母，其中通过数为分子。它不是去重输入数或不同输出数。
- `md` 或秒懂页面的原生汇总可能使用不同分母，例如把空跑纳入执行次数。不用原生通过率替代业务通过率，也不把两者混为一个数字；需要并列时分别写明口径。
- 空跑 `noop` 和未跑 `not_run` 各自单列，都不进入业务通过率分母。空跑不是正常失败；未跑也不是已完成执行。总记录数、正常可判定数、空跑、未跑、完成状态未知、判定缺失和异常状态必须分开显示。
- 源数据有 failed/error/timeout 状态而没有明确 passed 时不能猜成 false；需显示异常并披露未纳入通过率分母。业务要把这些计入失败须确认规则并另列该口径，不能悄悄更改基础指标。
- 已确认调整用新的报告判定统计，原始判定保存用于追溯，不让旧失败原因继续冒充当前结论。
- 零分母显示“不适用”，不能显示 0% 或 100%。
- 去重精确匹配 input + context + actual，不做语义合并，不删换行或标点。保留每个变体的执行次数和通过/失败/未纳入统计次数。

## 转人工

可接受证据：已执行的转接事件、明确成功的 handover 工具调用/动作结果，或已核验含义的结构化布尔字段。

不可单独作为证据：预期中的 handover、待执行的工具计划、模型说“帮您转人工”、出现客服关键词、或仅看最终回复没有转接字样。

脚本不会自动猜原始 API 的转人工字段。agent 检查当前部署的真实字段/轨迹后，用 annotations 指定每次执行的 true / false / null 和依据；false 需要能排除该执行实际发生转接，数据不全保持 null。

默认：转人工执行次数 ÷ 正常完成且是否转人工明确的执行次数。同步展示全部正常完成数、未知数、识别覆盖率，并解释“这是已识别样本的转人工率”。该分母不要求业务判定为布尔值：转人工口径与业务通过率独立。一个执行多次转接计一次；若用户要事件次数或会话口径，另设清晰指标，不偷换分母。转人工状态不直接影响测试是否通过。

“应转未转”“不应转却转”需要逐场景预期；无规则则标注无法判断，不根据转接率高低评价质量。

## 其他常用内容

- 分场景/渠道/意图：使用已存在且含义明确的字段；缺失分组单列，不按案例名随意猜。
- 耗时：确认字段单位，只纳入正常完成、非负且有限的样本；空跑、未跑、错误或状态未知不混入业务耗时。列有效样本数、缺失数、均值以及需要时的分位数定义。耗时分母不要求业务判定已知，与通过率口径独立。
- 稳定性：同输入同上下文的重复执行，分析不同实际输出及混合判定；措辞不同不必然代表质量不同。
- 版本对比：明确双方数据完整、匹配键、相同分母和统计标准；不能把不同测试集的比例直接当作版本提升。
- 自定义指标：在任务目录写可重复计算代码，保存数据来源、规则与证据，再按 data-contract 的 metrics 输出；renderer 只校验结构，不证明业务统计真实。
- 自定义章节：sections 支持文字和表格；图表、额外字段或特殊分析可在任务范围内扩展输出。扩展后重跑一致性、安全和页面检查，不声称任意需求已被内置脚本自动支持。

## 报告生成后的核对

对照原始记录核对总数及分母；所有失败都可定位到完整实际输入输出；各去重变体出现次数相加等于全部记录数；自定义指标可复算；unknown 没被当 false；HTML 没有可执行的源内容、凭证、内部原始元数据或无关文件。输入输出需要脱敏时保留私有原文，公开版显式说明脱敏，不假称完全原文。
